# Virtual Page Find (0.2.19)

Experimental Firefox and Chrome Manifest V3 extension for finding literal text in scrollable/virtualized web pages. Built from scratch; no runtime or build dependencies. The browser toolbar popup controls a scan in the top frame. It never injects a panel into the website.

## Build and load

From this directory, run `python3 build.py` (Python 3.9+). Output: `dist/firefox/`, `dist/chrome/` and deterministic ZIP archives.

- Firefox 140+: open `about:debugging#/runtime/this-firefox`, select **Load Temporary Add-on**, and choose `dist/firefox/manifest.json`. Temporary installs disappear on browser restart. Permanent normal installation requires Mozilla signing.
- Chrome: open `chrome://extensions`, enable Developer mode, click **Load unpacked**, select `dist/chrome/`.

Open a normal website, click the toolbar icon, select its scroll container (largest visible scrollable area is suggested), enter a literal query, choose a scan speed and click Scan. Normal waits at least 550 ms per view; Fast 250 ms is suitable for static/quickly updated pages, Slow 1000 ms for debounced rendering. Very slow or continuously changing pages can still exceed the wait or overall scan limit. Results appear in page order with context and approximate vertical offset. Click a result to navigate; verification can fail if the layout changed. Copy matches copies plain text. Clear discards the current results. Stop cancels scanning; the original numerical scroll position is restored unless the user interrupted by interacting with the page. Closing the popup does not stop a scan; reopen to see progress. Results live only in the injected isolated-world memory until cleared or navigation/reload.

## Safety and scope

Only `activeTab` and `scripting`: no host permissions, background scripts, persistent storage, telemetry, network requests, remote code, dependencies, cookie/history access or website DOM modifications. The extension does scroll the page, which can naturally trigger the site's own network activity or lazy loading. It does not inspect API responses or private application state.

Scanning starts at the top, overlaps viewports, waits for mutations and scroll geometry to settle, and checks the bottom twice. The scanner reports limits, stalled scrolling, detected traversal gaps and cancellation separately from layout uncertainty. A lazy-rendered page may resize without user interaction; if both ends are reached after a range change during scanning, the status is “Reached both ends — results uncertain (layout changed)”. Matches may be missing or duplicated and jump positions inaccurate. Detected gaps and other problems still produce an incomplete status; **even a traversal that reaches both ends is best effort**, not proof that all data was loaded. Repeated hits are deduplicated heuristically by match/context and coordinates; persistent sticky/fixed labels use text-node identity and offset instead. Recycled/recreated pinned nodes remain best effort. Negative scroll offsets in horizontal-writing-mode column-reverse flex containers are normalized. Text wholly clipped by ordinary overflow ancestors is excluded; this is not pixel-perfect occlusion detection. Text is searched across adjacent inline text nodes within a block; no general rendered-text normalization. Only the selected vertical scroll container is scanned, not all nested scroll areas, shadow roots, cross-origin frames, canvas, pseudo-elements or virtualized columns. Literal searches only in v0.1; arbitrary regex intentionally omitted to avoid blocking the page with pathological regex. Page interactions stop the scan. Safety caps: 180 seconds, 1200 views, 1000 results, 80000 text nodes or 2 million characters per view. Restoration/jump can be inaccurate when scroll geometry changes. No actual ChatGPT account data was used to develop this version.

## Test

`node tests/core.test.cjs` exercises the actual search, overlapping steps and deduplication helpers (Node 18+).
For a browser smoke test, run `python3 -m http.server 8000` here and visit `http://localhost:8000/tests/virtual-list.html`. Load extension, select main list, search Yesterday. Expect 7 hits, including identical consecutive labels and split inline text; initial scroll position should be restored. Case-sensitive mode should yield 6. Test cancellation, copy, navigation and popup reopen. Repeat in Firefox and Chrome, then on a long ChatGPT task conversation. Firefox 0.1.1 was manually tested on a long ChatGPT scheduled-task conversation (six expected Yesterday hits found). Native popup opening speed and the revised layout status in 0.1.2 still require manual validation.

Automated DOM-engine integration test (not the extension popup/API integration): `npm install --no-save --package-lock=false playwright@1.56.1`, `npx playwright install chromium firefox`, then `node tests/browser-smoke.mjs all`. Playwright is optional, development-only, and never included in the packaged extension. The test checks container discovery, exact match counts and order, split text, identical labels, navigation, restoration and cancellation.

Regression fixtures cover 350 ms debounced rendering, repeated sticky labels, negative scroll offsets and nested overflow clipping in both browsers.

Version 0.1.2 adds browser regressions for dynamic range growth, a real traversal gap, and popup CSS width independence from the initial viewport and long text. These do not measure native browser popup animation.

## Diagnostic log

Expand **Diagnostic log (local)** during or after a scan to inspect the live log and copy it. It records the UTC start time, relative timings, selected speed, viewport geometry, scroll targets and actual positions, mutation counts while waiting, new/total match counts, range changes, cancellation and completion. It contains no page URL, query, matched text, DOM IDs or raw exception messages. Up to 4096 records are kept in tab-local memory; oldest records are dropped if necessary. A new scan, Clear or page reload discards the old log. The popup requests log data only while the section is open. No additional permissions or persistent storage are required.

Version 0.1.3 adds prepend/reflow uncertainty, log privacy and popup warning/display regression checks. The tests do not guarantee completeness after reflow or measure native popup latency.

Version 0.1.4 adds the transparent magnifier / vertical double arrow icon, in 16, 32, 48 and 128 px PNG sizes. Firefox uses theme-specific dark and light toolbar icons; Chrome uses a neutral gray icon. All are derived from the same alpha silhouette. Native toolbar appearance still needs manual validation.

Version 0.1.5 moves the explicit popup width from `:root` to `body` as recommended by Mozilla for standards-mode action popups, following a real Firefox report of a native popup approximately twice the content width. The body is 389px including padding. Tests exercise 100/389/800px viewports with long result, option, warning and diagnostic text. Native Firefox toolbar sizing must still be retested manually.

## Verified navigation (0.2.0)

By default, a scan which reaches both ends but observes range changes repeats once from the top within the original time/view limits. The second pass replaces first-pass results rather than combining incompatible coordinates; if incomplete, the original results are retained with a warning. Turn off **Recheck after layout changes** for a single pass. A stable second pass is not proof of completeness.

Where available, matches store a unique application-owned DOM identifier (data-message-id, data-turn-id, data-item-id), or a generic HTML id on or inside the matched text block, relative text-node paths and match offsets. A generic ID on an enclosing list, spacer or other ancestor is not accepted as a row identity; unkeyed virtual rows fall back to coordinate/context deduplication and approximate navigation. Identical text in different identified elements remains separate. Navigation checks the same identifier, paths, offsets and context; if currently mounted, it recalculates the target position. Without identity evidence, matching text at the expected position is only approximate. IDs may be recycled or change; verification is DOM identity evidence, not semantic ground truth. No DOM mutation, new permission or network request. Diagnostic logs record numeric jump geometry and outcomes, not IDs or text.

**Verify all positions** visits up to 100 results, reports verified/approximate/not found counts and per-result outcomes, and restores the pre-check scroll position unless manually interrupted. Stop cancels the check. This checks consistency of the recorded matches, not whether the search missed anything. For an independent oracle, serve the repository using the existing local HTTP server and open `http://localhost:8000/tests/navigation-fixture.html`. Search Yesterday in the main container; four identical matches are expected. Playwright additionally asserts each jump lands on its known test-only oracle marker (not read by the extension), and verifies rejection of an identical-text replacement with a different identity.

Version 0.2.1 fixes the 0.2.0 integration-test regression where a persistent virtual-list spacer ID plus a changing child-node path created duplicate hits or merged independent rows. Regression coverage includes a 350 ms debounced list and three identical unkeyed rows under one shared ancestor ID; no verified identity is claimed for those rows.

Version 0.2.2 adds sequential navigation replay when a direct jump cannot locate the saved occurrence. It starts from a stable top and uses the same overlapping viewport steps and mutation/geometry quiet checks as scanning. Batch verification reuses the forward replay cursor. A replay still requires matching context and coordinates for an unanchored hit and never calls it verified; it does not substitute a nearby occurrence. Navigation shares a 180-second/1200-step budget per operation, and page input interrupts it. The log distinguishes direct attempts, replay steps and final outcomes. The new browser fixture simulates a virtualizer that rejects large jumps and uses independent oracle rows. This is a reproduction of the observed failure mode, not the actual ChatGPT implementation.

## Optional real shared-chat CI smoke test

Set the repository Actions secret `VPF_SHARED_URL` to a publicly viewable `https://chatgpt.com/share/…` URL (not a private conversation URL). Optionally set repository Actions variable `VPF_EXPECTED_COUNT` to the independently known number of case-insensitive “yesterday” matches on that specific snapshot. The same-repository PR CI automatically runs the Firefox live test after each relevant commit; without the secret the job reports disabled. The share URL is not committed or logged. No authentication, screenshots, DOM dumps, page text, raw exceptions, IDs or URL are published; logs contain only status, geometry, counts, fixed attribute names and navigation outcomes. Access challenges, unavailable conversation DOM or redirects stop the test rather than attempting a bypass. A public share snapshot can differ from the signed-in conversation, including its virtualization and timestamps. Approximate matches remain unverified; expected count is optional because snapshots can differ. Use a non-sensitive test conversation. For local testing, run the same script after installing Playwright Firefox with the URL in the environment.

Version 0.2.3 permits the bounded second pass to recover transient first-pass scrolling/settling warnings, even when the first pass stalled. The original warnings are retained in diagnostics; only a clean complete retry can replace first-pass results. Fatal inspection limits and cancellation do not trigger retries. Live CI additionally publishes allowlisted scan events, fixed warning codes and bounded ancestor-structure summaries (attribute presence only, no page text or attribute values).

Version 0.2.4 increases the bounded per-view settling timeout to 4 seconds in both scanning and navigation. The minimum wait and 160 ms quiet condition are unchanged; continuously changing views still produce a warning or unsuccessful navigation. Live CI now counts nearby application record attributes, without logging their values, to investigate safe sibling-record anchors. The 2-second asynchronous-rendering regression preserves the existing quiet-window requirement.

Version 0.2.5 adds a conservative sibling anchor for a date/label next to a unique data-turn-id element in the same local wrapper: exactly one turn record, separate branches, maximum three levels to the record, and another record in the wrapper's parent. Ambiguous wrappers remain unanchored. This uses a real observed shared-chat structure, not a site URL check. Replay can continue through a DOM-busy but geometrically quiet view; the scan still retains its timeout warning. Anchored replay is not stopped by the old numeric match coordinate. The live test records bounded mutation-type/visibility counts at the busiest positions, never page text or IDs.

Version 0.2.6 allows a bounded ancestor search for a sibling turn record (eight levels from text, six from wrapper to record), while preserving the single-record/local-wrapper and uniqueness checks. Settling now distinguishes mutations whose target and rendered contents lie outside the selected viewport from visible or uncertain changes. ### Shared snapshot clock oracle

The live test uses the six user-supplied timestamp labels of the configured reference snapshot as an ordered oracle. Both Berlin and UTC browser contexts run with English locale and a fixed November 28, 2026 browser date (normal timers remain active). The timezone hypothesis predicts all six in Berlin, and only ordinals 2–6 as Yesterday in UTC. CI reports only ordinal matches, not recovered label text, and checks all navigation identities. The separately sampled mounted labels are diagnostic evidence, not a complete independent traversal. A different snapshot requires a different oracle. `VPF_EXPECTED_COUNT`, if set, applies to the Berlin case.

Version 0.2.7 distinguishes navigation from scan settling: already-visible exact matches are left in place after a short identity check, and a direct move can finish when the exact target stays visible even if unrelated DOM or scroll geometry is busy. If a direct move fails, an anchored target can be recovered through at most four local viewport steps before falling back to the existing top-to-bottom replay. Unanchored equal text is never promoted to Verified. Live Berlin CI exercises individual backward and repeated jumps (ordinals 5, 3, 3), reports timing, final visibility and replay usage, and checks a repeated visible click does not scroll. Synthetic regression exercises sustained viewport jitter and identical labels.

Version 0.2.8 extends the bounded local fallback to probe adjacent overlapping viewports even when the direct landing exactly matches the stored coordinate. The real backward jump must not use full replay in the Berlin live test. A regression explicitly unmounts a target at its old location and remounts it only after a small backward move; an identically worded second result does not count as success.

Version 0.2.9 uses the last verified and still-visible result as a relative navigation origin when a nearby logical target is unmounted. It follows the recorded result order (including backward moves) rather than assuming stale pixel coordinates preserve that order across re-estimation. At most 14 overlapping moves or 12 seconds before the existing direct/local/full fallbacks; an exact anchor and context must still match. A regression deliberately inverts the relationship between the current source coordinate and the older target's stored coordinate. No application-specific index or network state is accessed.

Version 0.2.10 requires every non-whitespace fragment of an anchored matching text range to be fully inside its clipping bounds before navigation reports Verified. Scanning still records intersecting text as before. Independent synthetic navigation oracle now checks the actual text range of the known oracle row (rather than requiring the full card to fit); an additional fixture specifically clips the word and requires navigation to make it fully visible. Live individual-jump diagnostics report relative/local step counts and replay starts.

The Berlin live test additionally exercises a continuous mixed-order sequence of individual jumps across the six reference dates (short/long forward and backward, including adjacent forward then full-distance backward). It checks the exact timestamp independently immediately and 500 ms after navigation, logs ordinal-only timings, fallback counts and visibility transitions, and preserves the original backward and repeated-click assertions. Engine code is unchanged; new combinations measure replay use rather than forbidding the correctness fallback.

Version 0.2.11 adds automatic local click tracing without changing navigation strategy. The diagnostic journal correlates individual result ordinals and click IDs, coarse browser/platform/version and viewport metadata, anchor lookup failure reasons (not values), strategy eligibility, requested/clamped/immediate/settled scroll coordinates, geometry extrema, relevant mutation counts, identity/context/clipping counts, and fallback reasons. Post-click samples at about 150, 500 and 1200 ms detect late reflow; observation stops on intervening page input or a new operation. The popup shows the last click's method, outcome and duration and copies a fresh journal. The same tab's content script retains logs across popup close/reopen; new scan, Clear or page reload clears them. The journal remains bounded to 4096 records and contains no query, page text, raw DOM identifiers, URL, raw UA or exceptions. No network or storage permissions added. Click tracing and post-observation may add small diagnostic overhead; CI and local timing should be compared with the same version.

Version 0.2.12 recognizes unique ancestor `data-content-search-turn-key` and `data-turn-key` attributes, observed in the signed-in virtualized ChatGPT transcript. Existing message/turn/item ID priorities and generic-ID safeguards remain unchanged. Missing or ambiguous keys fall through to the next supported attribute. Keys and text paths are checked again on navigation; values are never logged. A remounting fixture mirrors the observed nested `data-virtualized-turn` → `data-turn-key` → `data-content-search-turn-key` → timestamp structure, including missing and duplicate keys. Actual signed-in browser verification remains manual; public shared-chat CI covers the existing sibling-anchor path.

Version 0.2.13 addresses PR review: reconcile overlapping observations of the same record when its anchor appears or text path changes at the same coordinates; do not accept a conflicting known anchor as an approximate navigation success; refresh container discovery when a popup reopened during navigation becomes idle. Existing fallback strategies remain unchanged.

Version 0.2.14 experiments with two bounded navigation optimizations. For an unmounted forward target near a still-visible verified source, a nonzero observed source displacement supplies a corrected direct landing coordinate if it is inside the current scroll range. Backward targets retain the existing relative strategy. After a failed direct move, one corrective retry uses fresh mounted geometry or a substantial scroll-range delta as a hint; subsequent local recovery uses the updated estimate. Every success still requires the existing identity/visibility checks. No scan or navigation wait changes in this experiment. New tests model a uniform prefix shift and a direct landing that collapses the prefix and unmounts the target. Live CI reports prediction and correction attempts separately.

Version 0.2.15 responds to live 0.2.14 traces: a long failed jump to an already mounted target is not repeated, and local recovery may continue up to ten overlapping moves while the exact target remains mounted (only four speculative probes without it). For backward navigation only, the existing relative strategy now covers up to 12 saved viewports and 20 steps within its unchanged 12-second budget. This avoids a premature full replay when a mounted target is just beyond the former four-step limit or a verified older target is slightly beyond nine viewports. No new strategy or verification relaxation; wait timings are unchanged.

Version 0.2.18 preserves the direct fast path for distant mounted targets until an anchored target has actually been observed unmounted during navigation. A timed-out relative step falls back immediately instead of consuming the entire relative budget on a busy viewport. This retains the original busy-viewport regression test unchanged.
